# 前端协作

只改本仓库。用户是 10 年前端，页面可以一起打磨。

**先看** `../zhibo-shared/docs/工单.md`，再读 `项目背景.md` 和 `API约定.md`。

## 问清再干（强制）

用户提的**所有**问题与需求，一律按下面做：

1. **有不清楚的 → 先问用户**（范围、文案、交互、接真接口还是 Mock、改哪一页等），问清楚后再动手。
2. **没有不清楚的 → 直接干**，不要为了「走流程」硬问一堆。
3. 问的时候一次把关键点列清，等用户答完再开工；中途又冒出歧义，停下来再问。

不要猜需求、不要擅自扩大范围。缺后端接口：写 `docs/进度.md` 阻塞项，不要造后端。

## 可以改

- `admin-web/**`
- `live-web/**`
- `docs/进度.md`
- 本文件与 `AGENTS.md`（协作约定变更时）

## 已定约束（细节以 shared 为准）

- Vue 3 + TS + Vite + UnoCSS
- `admin-web` 5173 → `/api` 8081；`live-web` 5174 → `/api` 8082
- 成功：`code === 0`
- 禁止直连微吼、禁止 `app_secret`
- 不要改回 h5-web
- **主题色 / 设计 token**：见 [设计规范.md](./设计规范.md)；实现 `admin-web/src/styles/theme.css`；业务禁止写死品牌色，用 `var(--color-primary)` 等变量

## 单文件体量

- **尽量 ≤500 行**（含 template / script / style）。
- **特殊情况可到 600 行**；再往上必须在 PR/进度说明里写清合理理由。
- **超过 600 行**：先拆再合——拆组件、拆 composable/hook、拆纯函数/常量/类型、拆样式等，凡是能降低单文件复杂度的手段都可以用；不要为「省事」堆在一个文件里。

## 不可以改

- `../zhibo-backend`、`../zhibo-shared`
- 端口、代理目标、目录名

缺接口：写进度阻塞项，不要造后端。
